    一、HTML

    1.1 DOCTYPE的作用

    • 作用：声明文档类型，未声明会触发怪异模式-导致页面布局样式出现问题
    • 方式：<!DOCTYPE html>

    1.2 HTML语义化

    • 核心：用合适的标签表达内容含义（正确的标签做正确的事）
    • 好处：
      • 代码可读性高
      • 有利于SEO
      • 提升无障碍访问（方便屏幕阅读器解析）

    1.3 块级元素 vs 行内元素

    • 块级元素(div)：独占一行，可设置宽高，默认宽度100%
    • 行内元素(span)：不换行，不可设置宽高，宽高基于内容调整
    • 行内块元素：display: inline-block

    1.4 HTML5新特性

    • 语义化标签：header，footer，article
    • 本地存储：localStorage,sessionStorage
    • Canvas/WebGL：图形绘制
    • 新技术Web Worker，Web Socket(双向通信协议)

    1.5 meta 标签

    • 作用：定义网页元数据，控制编码、视口适配、SEO和浏览器行为。

    1.6 script标签async和defer区别

    • 无属性：立即执行，按顺序执行，阻塞html解析
    • async：谁先加载完谁先执行 - 适合独立脚本，如统计代码，可能阻塞html解析
    • defer：按顺序执行 - 适合依赖 DOM 的脚本，不阻塞html解析（html解析完顺序执行）

    1.7 浏览器渲染 HTML 的过程

    • 过程
      • 解析 HTML → 构建 DOM 树
      • 解析 CSS → 构建 CSSOM 树
      • 合并 DOM + CSSOM → 生成渲染树
      • 布局（Layout） → 绘制（Paint）

    1.8 SEO优化

    • 语义化标签
    • 图片优化：img标签添加alt属性
    • URL友好：使用短横线分隔（/details）

    二、CSS

    2.1 盒模型

    • 标准盒模型：元素width/height = content的宽高
    • ie盒模型：元素width/height = content + padding + border
    • 切换：box-sizing: content-box(默认) 或 border-box（推荐使用）

    2.2 BFC-块级格式化上下文

    • 定义：一种独立的布局环境，内外互不干扰（玻璃罩）
    • 触发方式：
      • float: left/right; /* 浮动 */
      • overflow: hidden/auto; /* 溢出隐藏 */
      • position: absolute/fixed; /* 绝对定位 */
      • display: inline-block/flex/grid/table-cell; /* 特殊display值 */
    • 作用：
      • 外边距重叠 - BFC隔离
      • 清除浮动-浮动元素高度塌陷 - BFC包含
      • 阻止文字环绕 - BFC阻止
    • 示例：
    <!-- 外边距重叠 -->
<div style="overflow: hidden;"> <!-- 触发BFC -->
    <div class="box1">上边距20px</div>
</div>
<div class="box2">下边距30px</div>
<!-- 浮动元素高度塌陷 -->
<div style="overflow: hidden;">
    <div class="float-child" style="float: left;">浮动元素</div>
</div>
<!-- 文字环绕 -->
<div class="float-left" style="float: left; width: 100px;">浮动块</div>
<div class="text">这是一段很长的文字会环绕浮动元素...</div>
.text {
    overflow: hidden; /* 触发BFC，文字不再环绕 */
}

    2.3 水平垂直居中的方式

    • flex布局
    • 绝对定位 + Transform
    • Grid
    .parent { 
    display: grid; 
    place-items: center;
}

    2.4 flex和Grid的区别

    • flex: 一维布局
      • flex: 1 => ==> flex:1 1 auto; ==> flex-grow:1;flex-shrik1;flex-base:auto;本身大小
    • grid：二维布局 - 解决复杂网格布局
    /*九宫格 */
.container {
    display: grid; /* 激活 Grid 布局 */
    grid-template-columns: repeat(3, 1fr); /* 定义三列，每列的宽度相等，宽为1/3 */
    grid-template-rows: repeat(3, 100px); /* 定义三行，每行的高度为 100px */
    gap: 10px; /* 设置行列之间的间距 */
}

    2.5 回流和重绘

    • 定义：
      • 回流：布局变化触发重新计算（修改元素尺寸）
      • 重绘：样式变化但布局不变化（修改颜色）
      • 回流一定会触发重绘，重绘不一定会回流
    • 回流重绘影响浏览器性能，优化方式：
      • 避免重复操作dom
      • 使用transform/opacity触发GPU加速（减少重排）// 浏览器通过GPU处理这两个属性，而不是重新计算整个页面的布局

    2.6 伪类vs伪元素

    • 概念
      • 伪类(单冒号)：描述元素状态。如：:hover，:first-child等
      • 伪元素(双冒号)：创建虚拟元素。如：::after清除浮动等

    2.7 postion定位

    • 分类
      • static:默认值，没有定位
      • relative:(相对定位)相对于元素原来位置进行定位
      • absolute:(绝对定位)相对于最近的有定位的父元素进行定位，脱离了文档流
      • fixed:(固定定位)相对于浏览器窗口定位，脱离了文档流
      • sticky:(粘性定位)relative和fixed的结合，根据滚动的位置进行定位

    2.8 css选择器优先级

    !important > 行内 > ID > 类 > 元素

    2.9 css预处理器有哪些

    • 定义：通过编程方式增强CSS的工具，需编译为原生CSS
    • 核心优势：变量，嵌套，混合（Mixins）-代码复用，模块化（@import）
    • 分类
      • less
      • sass - 无花括号 - scss
    • less和sass比较
      • sass：更强大，支持循环、条件语句

    2.10 固定单位和相对单位

    • 区分：
      • px：固定单位，像素值（精确控制元素的尺寸 - 按钮，图标）
      • rpx：响应式像素，根据屏幕宽度（750rpx）自动适配（微信小程序专用单位）
      • em：相对单位，基于当前元素或父元素的字体大小，继承链会影响值
      • rem：相对单位，基于根元素的字体大小
      • vw,vh：基于视口大小，适合响应式设计（全屏背景图）
      • %：依赖父元素，属性不同基准不同

    2.11 响应式布局的实现方式

    • 方式：
      • 媒体查询 - 针对不同的屏幕尺寸设置不同的样式
      • Flexbox/Grid - 内容自适应排列
      • 相对单位（vw/rem） - 整体比例缩放
    • 示例
    @media (max-width: 768px) {  
    .container { padding: 10px; }  
}

    2.12 css3新特性

    • 分类
      • 盒模型
      • 动画
      • 弹性布局
      • 阴影
      • 选择器（:first-child）

    2.13 css动画

    • transition：过渡效果，需要触发，单次动画
    • animation：复杂动画，自动或触发均可，可循环，暂停

    三、Javascript

    3.1 js数据类型及判断方法

    • 分类
      • 基本数据类型：存放在栈内存中
        number,string,boolean,undefined,null,symbol,bigInt
      • 引用数据类型：存放在堆内存中
        object,array,function
    • 判断数据的方式
      • 基本数据类型判断：typeof（对于引用数据类型和null返回object）
      • 引用数据类型判断：instaceof（判断对象是否是构造函数的实例，会沿着原型链查找）
      • 数组的判断：Array.isArray, constructor, Object.prototype.toString.call([])===’[object Array]’
      • 构造函数判断：constructor
      • 通用类型判断：Object.prototype.toString.call()
    • 相关概念
      • Symbol：独一无二的值（解决命名冲突问题）
      • bigInt：大整形–更大数值运算
      • 包装类
        • 概念：基本数据类型通过包装类可以调用属性和方法。
        • 特点：包装类执行完成后会立即销毁
        • 三种包装类：Number(),String(),Boolean()
        let num = 42; // 基本数据类型：数字
console.log(num.toString()); // 自动将数字转为字符串
      • instanceof 和 constructor判断区别：
        • instanceof：判断对象是否在构造函数的原型链上
        • constructor：判断对象的直接构造函数（只能判断引用数据类型）
        // instanceof
[] instanceof Array // true
[] instanceof Object // true
// constructor
console.log([].constructor == Array) // true
console.log([].constructor == Object)  // false

    3.2 js函数相关

    • 函数类型
      • 1.普通函数 function Test(){ return arguments }
      • 2.箭头函数 let num = (a, b, …rest) => { return … }
      • 3.立即执行函数 let num = (function () { return 8 + 9}())
      • 4.异步函数 async function test() {}
      • 5.生成器函数 function* gen() { yield } – 可暂停执行（yield）
    • 箭头函数和普通函数区别
      • 1.普通函数：可以作为构造函数，有自己的原型对象，有实参列表arguments，this指向undefined/window
      • 2.构造函数：不可以作为构造函数，无自己的原型对象，无实参列表arguments，无自己的this，继承于外层
    • 函数中的this指向问题
      • 普通函数：严格模式指向undefined，否则指向window
      • 对象中函数：指向对象
      • 构造函数，this指向新创建的实例对象
      • 箭头函数：继承外层作用域的this
    • 修改this指向：call, apply, bind
      • 作用：改变函数内部的this指向(让函数的this指向对象)
      • 区别：
        • call,apply改变this指向后便执行该函数，bind返回一个新函数必须手动调用
        • call和bind一个参数一个参数传，apply以数组的方式传
      • 示例
      // func.apply(thisArg, [argsArray]) // 把func函数内部的this指向对象thisArg，并执行函数
function greet(name, age) { 
    console.log(`hello ${name}, i am ${this.name}` )
}
const person = { name: 'zhangsan' };
greet.apply(person, 'lisi'); // hello lisi, i am zhangsan

    3.3 原型和原型链

    • 构造函数：创建对象的模板
    • 原型：构造函数自带的共享存储库（存放所有实例共享的方法）
    • 原型链：对象通过__proto__向上查找属性的链条
    • 相关概念：
      • new 一个对象的过程（1空2链3绑4返）
      function Person(name, age) {
    this.name = name;
    this.age = age;
}
let person1 = new Person('张三', 16);

// new一个对象的过程
1.创建空对象：var obj = {};
2.链接原型：
    obj.__proto__ = Person.prototype; // obj 继承Person.prototype上的属性和方法
    obj.constructor = Person; // 指定构造函数
3.绑定this：Person.call(obj) // 让函数的this指向这个对象
4.返回对象：返回obj对象
      • 为什么实例对象可以访问原型对象里面的属性和方法
      对象.__proto__ == 构造函数.prototype
对象.constructor = 构造函数
构造函数.prototype.constructor == 构造函数
构造函数.prototype.__proto__ == Object.prototype
Object.prototype.__proto__ == null
// 示例
function Star(){}
let star = new Star();
console.log(star.__proto__ == Star.prototype) // true
console.log(star.__proto__.constructor == Star.prototype.constructor == Star) // true

    3.4 js继承方式

    • 目的：构建可复用的组件体系
    • 方式
      • (1)通过原型链继承 - 适合方法继承（引用类型属性共享是致命缺陷）
      • (2)通过构造函数继承 - 适合属性继承（方法无法复用共享）
      • (3)寄生组合式继承 - 最优解（构造函数拿属性，原型链拿方法，Object.create做桥梁）
      • (4)ES6 Class继承 - 底层基于寄生组合式继承
    • 应用场景：组件扩展，公共逻辑复用，UI 组件库开发，vue组件继承(extends)
    • 现代开发建议：优先使用 ES6 Class 语法
    • 代码实现
    // 1.原型链继承
function Father() {
    this.hobby = ['看书'];
}
Father.prototype.say = function(){
    console.log(this.hobby);
    return;
}
function Child(){}
Child.prototype = new Father();
let child = new Child();
let child1 = new Child();
child.hobby.push('睡觉');
console.log(child.hobby); // ['看书', '睡觉']
console.log(child1.hobby); // ['看书', '睡觉']

// 2.构造函数继承
function Person(name, age) {
    this.name = name;
    this.age = age;
}
function Student(name, age, grand) {
    Person.call(this, name, age);
    this.grand = grand;
}
let student = new Student('张三', 18, 88);

// 3.寄生组合式继承 
function Father(name, age) {
    this.name = name;
    this.age = age;
}
Father.prototype.say = function(){
    console.log(this.name);
}
function Child(name, age, hobby){
    Father.call(this, name, age);
    this.hobby = hobby;
}
Child.prototype = Object.create(new Father());
Child.prototype.constructor = Child; // 修复构造函数

const child = new Child('zs', 18);
console.log(child.name)
console.log(child.say());

// 圣杯模式
let inherit = (function(){
    function F(){}; // 私有化变量，立即执行函数，执行后即销毁
    return function(Target, Origin){
        F.prototype = Origin.prototype;
        Target.prototype = new F();
        Target.prototype.constructor = Target;
        Target.prototype.uber = Origin.prototype;
    }
}());
// 使用Object.create简化
let inherit = (function() {
    return function(Target, Origin) {
        Target.prototype = Object.create(Origin.prototype); // 使用 Object.create 建立原型链
        Target.prototype.constructor = Target; // 修复构造函数指向
        Target.prototype.uber = Origin.prototype; // 保留对父类原型的引用
    }
}());

    3.5 闭包

    • 概念：函数里面嵌套函数，并把内部函数返回出来。内部函数可访问其定义时的作用域
    • 作用：
      • 创建私有变量：防止外部直接修改重要数据
      • 状态保持：函数多次调用需要记住之前的状态
      • 函数工厂：需要批量创建功能相似的函数
    • 内存相关：
      • 内存泄漏：无用的内存还在占用，得不到释放和归还
        • 闭包
        • 被遗弃的定时器
        • dom元素清空还在引用
      • 内存溢出：
        • 内存加载数据过大
        • 代码死循环
    // 1.状态保持（含私有变量）
function counterFun(){
    let count = 0;
    return () => {
        count ++;
        return count
    };
}
let counter = counterFun();
console.log(counter()); // 1
console.log(counter()); // 2

// 2.函数工厂 - 问候语
function createGreeter(greeting) {
    return (name) => `${greeting}, ${name}!`; // 返回函数
}
const sayHello = createGreeter("Hello");
const sayHola = createGreeter("Hola");
console.log(sayHello("Alice")); // "Hello, Alice!"
console.log(sayHola("Bob"));    // "Hola, Bob!"

// 相关实例
// 防抖：多次执行只执行最后一次
// 使用场景：输入框实时搜索
function debounce(func, delay = 300) {
    let timer;
    return function(...args) {
        clearTimeout(timer);
        timer = setTimeout(() => {
            func.apply(this, args);
        },delay)
    }
}

let obj = {
    name: 'zs',
    say: debounce(function() {
        // 执行操作而不是返回值
        console.log(this.name)
    })
}
obj.say()

// 节流：多次执行间隔执行
// 使用场景：按钮防止重复点击，拖拽操作
function throttle(func, interval = 300) {
    let lastTime = 0;
    return function (...args) {
        const now = Date.now();
        if (now - lastTime > interval) {
            func.apply(this, args)
            lastTime = now;
        }
    }
}

    3.6 对象的相关操作

    • 创建对象方式
      • 1.字面量 var obj = {};
      • 2.new Object() - 等价于对象字面量
      • 3.构造函数（可复用，实例共享原型方法）

var obj = new Person('张三');

    3.9 var let const区别

    • 区别
      • 作用域：var 函数作用域，let/const 块级作用域
      • 变量提升：var 存在变量提升，let/const 存在暂时性死区，声明前访问会报错
      • 赋值：var/let 可重复赋值，cosnt不能重新赋值（引用数据可修改内部属性）
      • 重复声明：var 允许重复声明，let/const 同一作用域禁止重复声明
    • 总结：优先用 const，需修改时用 let，避免使用 var
    • 相关概念：
      • 作用域：规定变量和函数的可使用范围
      • 作用域链：查找变量和函数时，从局部到全局依次查找
      • js执行：语法分析，预编译(创建当前环境的执行上下文)，解释执行
      • 预编译：全局预编译和函数预编译

    9.1 Cookie vs storage

    • cookie
      • 概念：存储在浏览器中不超过4kb的字符串。
      • 组成：
        • 一个名称（Name），一个值（Value）
        • 其他用于控制Cookie有效期，安全性，使用范围的可选属性
      • 特点：不同域名下的Cookie相互独立，浏览器请求时会自动发送未过期的Cookie到服务器端
    • 区别：
      • Cookie：4KB，可设置过期时间，无设置的话默认浏览器关闭失效。请求自动带。
      • LocalStorage：5-10M，永久保存，需手动清除。
      • SessionStorage：5-10M，标签页关闭失效。
      • Cookie,localStorage：在所有同源的窗口下可以共享，SessionStorage不同浏览器窗口不会进行共享。
    • 应用：
      • Cookie：token
      • localStoragea：用户主题设置
      • sessionStorage：表单草稿
    • 正常项目中为什么选择localStorage存储token？
      • 规避 CSRF（跨站请求伪造）：Token不随请求自动发送会天然降低CSRF风险
      • 跨域友好：避免Cookie的跨域配置复杂度
      • 前后端分离架构：前端需手动将Token加入请求头（如 Authorization），localStorage 更易控制

    9.2 web开发模式

    • 类型
      • 基于服务端渲染的传统web开发模式
        • 概念：服务端把拼接好的html页面发送给客户端
        • 优点：前端耗时少，有利于seo
        • 缺点：占用服务器资源，不利于前后端分离，开发效率低
      • 基于前后端分离的新型web开发模式
        • 概念：后端只提供接口，前端通过ajax调用接口
        • 优点：前后端分离，开发体验好。局部刷新，用户体验好。减轻了服务端的渲染压力
        • 缺点：不利于seo（利用vue,react等框架的SSR技术可以很好的解决seo问题）
    • web开发模式选择：根据业务场景
      • 企业级网站需要良好的seo：服务端渲染
      • 后台管理系统：前后端分离
      • 两者结合：首页服务端渲染 + 其他页面前后端分离
    • 身份认证的选择：
      • 服务器渲染 -> 推荐session认证机制
      • 前后端分离 -> JWT认证机制

    9.3 身份认证（鉴权）

    • 概念：通过一定的手段，完成对用户身份的确认
    • 相关概念
      • http协议的无状态性：服务器不会主动保留每次http请求的状态
      • token的组成：Header.Payload.Signature
        • Header：安全性相关
        • Payload：加密用户信息字符串
        • Signature：安全性相关
    • 方式
      • session认证
        • 流程
          • 1.浏览器 -> 发请求：提交账号 + 密码
          • 2.服务器 -> 验证账号和密码，将登录成功的信息存储到数据库中，同时生成对应的Cookie字符串。
            响应请求：将生成的Cookie通过响应头发送给浏览器
          • 3.浏览器 -> 自动存储Cookie到当前域名下
            再次请求：通过请求头自动将当前域名下的Cookie发送给服务器
          • 4.服务器 -> 服务器根据Cookie验明用户身份，浏览器根据当前用户生成特定的响应内容
        • 注意
          • Cookie不具有安全性：存储在浏览器中，容易伪造。所以不能使用Cookie存储重要且隐私的数据
          • 全程无需前端手动干预（浏览器自动完成）
          • Cookie不支持跨域，前端跨域请求后端接口时需要做额外的跨域配置
      • JWT认证
        • 流程
          • 1.浏览器 -> 发请求：提交账号 + 密码
          • 2.服务器 -> 验证账号和密码，将用户的信息对象经过加密之后生成Token字符串
            响应请求：将生成的token发送给浏览器
          • 3.浏览器 -> 将token存储在本地的localStorage/SessionStorage中
            再次请求：通过请求头Authorization字段，将token发送给服务器
          • 4.服务器 -> 服务器将token字符串还原成用户信息对象
            服务器根据用户信息对象确认用户身份，浏览器根据当前用户生成特定的响应内容
    • 注意
      • Session认证唯一性：服务器存储的Session ID（全球唯一），需查数据库
      • JWT认证唯一性：Payload中的用户ID(如sub) + 签名防伪，仅需密码学验签

    十、其他

    10.1 解决跨域方式

    • CORS（跨域资源共享）：后端设置响应头，允许指定域名的请求。（后端明确告诉浏览器允许跨域）
    • 代理服务器：前端通过同域的中间服务器（如Vite开发服务器、Nginx）转发请求，避开浏览器限制
    • JSONP：利用<script>标签无跨域限制的特性(仅限GET请求，已过时)

    10.2 浏览器缓存机制

    • 概念
      • 强缓存：直接读本地，不联系服务器（看过期时间）
      • 协商缓存：缓存过期后，问服务器「能用旧的吗？」
    • 应用：
      • 问题1：前端框架生成的静态资源可以通过强缓存来提高性能：强缓存 + 哈希文件名 - 控制缓存（内容变→文件名变→缓存失效）
      • 问题2：HTML被强缓存 → 用户看不到页面更新。 HTML文件：禁用强缓存（Cache-Control: no-cache），用协商缓存确保及时更新
      • 对于不频繁变化的API数据，可以利用协商缓存来减少请求量

    10.3 从输入URL到页面加载的过程

    • 1.URL解析：判断地址是否错误
    • 2.DNS解析：解析域名->ip地址
    • 3.建立tcp连接(tpc三次握手)
    • 4.发送http(https)请求
    • 5.服务器响应
    • 6.浏览器接受响应并解析渲染页面
    • 7.断开tcp连接

    10.5 WebSocket

    • 概念：一种网络通信协议，提供全双工（客户端，服务器端双向通信），持久连接的通信方式。
      基于 TCP 协议，允许客户端和服务器之间进行实时数据传输
    • 使用协议：ws,wss(加密的 WebSocket 协议)
      • ws：非加密的 WebSocket 协议
      • wss：加密的 WebSocket 协议
    • 应用场景：实时聊天应用，大屏推送

    10.6 虚拟列表（只渲染你能看见的，其他用空白占位）

    • 场景：适用于渲染大量数据时，尤其是当数据量大到无法一次性渲染到页面时，渲染数据量大，浏览器卡顿
    • 概念：动态渲染可视区域元素，优化长列表性能
    • 实现技术点：
      • 监听滚动事件
      • 动态计算可见区域（计算起始索引），添加缓冲区域
      • 动态高度支持 - 使用ResizeObserver监听每个列表项的实际高度
      • 性能优化 - 使用CSS transform实现位置偏移
        • GPU加速：现代浏览器会触发硬件加速
        • 避免回流：只触发重绘（Repaint），性能更好
        • 批量处理：只需修改单个属性即可移动整个可视区域
    • 总结：
      • 固定高度：定容器 → 算总量 → 截数据 → 移位置 → 渲可视
      • 动态高度：记位置 → 算索引 → 估高度 → 调位置 → 设缓冲
