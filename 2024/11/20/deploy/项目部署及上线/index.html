    前言

    • 服务器部署

      • 前后端同源
      • 前后端不同源

    • 部署位置

      • 介绍
        • 无论开发环境还是生产环境publicPath和路由base必须保持一致
          • 开发环境publicPath和base基本无需配置、
          • 生产环境部署在非根目录需配置publicPath和路由base
            • publicPath：静态资源(JS/CSS/图片) 的加载路径
            • 路由base：URL路径的路由匹配逻辑
      • 部署示例
        • 部署在根目录（https://www.example.com/）
        • 部署在子目录（https://www.example.com/sub-path）
          • 打包配置（可在打包后的html文件中看结果）
          <!-- 构建配置 -->
// vue2
module.exports = {
    publicPath: '/sub-path/'  // 必须带结尾斜线
}
// vue3
export default defineConfig({
    base: '/sub-path/' 
})

<!-- 路由配置 -->
// vue2
export default new VueRouter({
    mode: 'history',
    base: '/sub-path/',
})
// vue3（import.meta.env.BASE_URL取vite.config.js中的base）
const router = createRouter({
    history: createWebHistory(import.meta.env.BASE_URL),
})

    一、node部署

    • 技术点
      • express.static托管静态资源
      • connect-history-api-fallback：解决页面刷新找不到问题
        • 首次访问/路径，服务器返回 index.html
        • 刷新页面服务器在文件系统中找不到对应路径的文件
      • http-proxy-middleware：解决接口无法调用问题
        • 无代理服务器，无法访问后端
      • 代理相关
        • 开发环境
        export default defineConfig({
    server: {
        proxy: {
        '/api': {
            target: 'http://api.example.com',
            changeOrigin: true,
            rewrite: path => path.replace(/^\/api/, ''),
        }
        }
    }
})
// 解读
// 1. 浏览器请求: /api/users -> http://localhost:5173/api/users
// 2. 开发服务器代理转发: http://api.example.com/users
// 3. API 服务器返回响应
    • 代码
    const express = require('express');
const history = require('connect-history-api-fallback');
const { createProxyMiddleware } = require('http-proxy-middleware');

const app = express();

// 解决页面刷新找不到
app.use(history({}));
// express.static托管静态资源
app.use(express.static(__dirname + '/public'));

// 代理服务器
app.use(
  '/api-prod',
  createProxyMiddleware({
    target: 'http://124.222.47.39:9000',
    changeOrigin: true,
    pathRewrite: {
        '^/api-prod' : ''
    }
  }),
);

app.listen('8899', () => {
    console.log('服务器已启动')
})

    二、nginx服务器部署（本地）

    • 介绍：一款高性能的http服务器和反向代理服务器
    • 作用：
      • 1.反向代理
      • 2.负载均衡
      • 3.静态内容服务
      • 4.http/2支持
      • 5.SSL/TLS支持
      • 6.高速缓存
    • 使用步骤
      • 下载nginx。官网地址
      • 点击nginx.exe启动服务器
      • 验证启动：localhost:80/localhost
      • 修改nginx.conf中的配置
      • 根路径部署
      location / {
    root   E:\dist;
    index  index.html index.htm;
    try_files $uri $uri/ /index.html; # 解决刷新404
}

location /api-prod/ {
    # 设置代理目标，注意/api-prod/和http://124.222.47.39:9000/ 最后/不能少
    proxy_pass http://124.222.47.39:9000/;
}
      • 子路径部署（路由base和构建base需要同步添加子路径）
      location /sub-path/ {
    # 重要：使用 alias 而非 root
    alias  E:\dist;
    try_files $uri $uri/ /sub-path/index.html; # 解决刷新404
}

location /sub-path/api-prod/ {
    # 设置代理目标，注意/api-prod/和http://124.222.47.39:9000/ 最后/不能少
    proxy_pass http://124.222.47.39:9000/; # 注意结尾斜杠
}
